# P4 Pythia-70M Minimum Observation Plan v0.1

**Status:** `planned_not_frozen_not_run`

**Decision date:** 2026-09-04

**Claim ceiling:** design-only Level 0; any successor 70M run remains
claim-ineligible plumbing and integration validation

**Protocol-freeze, launch, execution, model, subject, network, raw-capture,
Pythia-70M, and Pythia-160M authority:** false

This document proposes the smallest model-observation campaign that could
exercise the [P4 measurement chain](P4_PHASE_CAPTURE_MEASUREMENT_CHAIN.md)
after a model-free partial-pattern prototype. It records an intended scope,
not an executable protocol, a frozen context bank, a resource reservation, or
permission to inspect model files or activations. No observation is reported
here. Furnace availability changes the future resource options, not this
document's authority: no remote connection, transfer, model download, or job
launch is part of this plan.

The purpose is to learn where a complete measurement branch becomes
evaluable, where it abstains, and which partial patterns merit a separately
versioned follow-up. It is not to require phase-like structure, cores,
holonomy, winding, or transitions to exist or to co-occur.

## 1. What is already known and what is not

The [consumed 70M GateState reconnaissance](EXPERIMENT_INTERPRETATION_LEDGER.md#330-consumed-exact-one-pythia-70m-gatestate-reconnaissance)
already measured Level-0 F2/F4 support diagnostics. Its partial support and
unavailable loop prerequisites are not observations that model fields, cores,
holonomy, winding, or phase-like regimes are absent. This plan does not rerun
that consumed identity, reuse its confirmation for selection, or fill missing
scalars by reconstruction. Verified-B D7 remains closed as its existing
descriptive `insufficient`.

The [M1 development prototype](P4_GRAPH_SCALE_TRANSPORT_PROTOTYPE.md)
demonstrated scale-transport/selection plumbing on its own synthetic fixture.
Its selected law, four confounded nuisance cases, and 8-by-8 structural `pass`
are not prospective calibration. Bounded endpoint-path support is not an
exact oriented loop identity. These limitations must not disappear when the
new prototype connects field estimation to loop readout.

## 2. Entry decision: first complete a synthetic measurement branch

The model-free predecessor should demonstrate one coherent path from
representation-shaped fit/evaluation probes through F2/F4 estimation,
same-field numeric payloads, charge-blind core candidates, declared-loop
support, and independent geometry/defect readouts. Directly supplying a perfect
final angular field is not sufficient to exercise this chain.

The development fixture must retain positives, null constructions, and
abstentions, including F2-only/F4-only eligibility, no-core coherence,
core-like amplitude depression without winding, geometry-only holonomy,
defect winding with flat geometry, cancelling opposite-sign dipoles, smooth
drift, gauge/reflection controls, zero amplitude, collapsed support, and
undersampling. A case name or injected anchor never substitutes for an
estimated field or inferred core.

A useful next decision requires at least one branch to distinguish its
positive, null, and ineligible constructions while retaining the other
branches' outcomes. It does not require every target to be positive. Passing
that development test does not qualify M9, SCI-S1, or a model null. A
prospective qualification successor would still need fresh fixtures,
thresholds, nuisance definitions, uncertainty rules, and a separate freeze.

Reception qualification must additionally address exact oriented boundary
binding, a crossed nuisance panel rather than jointly changing several
factors, and a finite density/locality range. A law with `k` proportional to
the number of rows preserves a neighbor fraction; it does not establish a
shrinking local neighborhood or a continuum limit.

## 3. Proposed first 70M observation envelope

The first separately authorized successor would use one checkpoint, one
shared early intervention position, and all six layers as a fixed panel.
Six layers is a planning assumption about the intended model, not metadata
verified or frozen by this document. Exact model/revision/tokenizer identity,
layer addresses, intervention/readout hooks, position index, and checkpoint
step remain unresolved until the future protocol establishes them.

The early intervention position is common across layers; it must not be
selected separately to improve each layer's outcome. Exact context lengths,
readout positions, the capture convention, and tokenization/truncation rules
must be declared before model observation. Layer is architectural depth,
not a time axis.

| Axis | Proposed bound | Still required before access |
| --- | --- | --- |
| Model/checkpoint | one intended 70M checkpoint | exact immutable identity and local access route |
| Intervention | one common early position; one two-dimensional domain | position, origin, coordinate basis, units, range, and input injection rule |
| Layer | all six layers, with no outcome-selected subset | verified architecture and exact capture addresses |
| Context roles | fit, discovery, and hidden confirmation | source inventory, grouping, assignments, counts, and access chronology |
| Section | F2 and F4, co-primary | separate specifications, floors, gauge laws, and split bindings |
| Graphs | three field-estimation families by three loop-support families | field-blind rules, exact boundary identity, support/locality budgets |
| Loops | nested, reverse, off-core, deformation, refinement, and enclosing-multiple-core families where applicable | predeclared domain classes and deterministic placement rules |
| Estimands | full response, pass-through baseline, local-linear baseline, and recomputed residual | independently bound numeric definitions and controls |

The three graph families are mutual-kNN, fixed-radius, and shared-neighbor.
The nine graph pairings refer to the same declared two-dimensional domain and
the same oriented loop classes, not nine independently chosen favorable
cycles. An extra core-graph axis is required if core estimation is neither
graph-free nor inherited from the field graph. Its cost cannot be silently
omitted.

Each F2/F4 field binds its actual numeric section, same-object amplitude,
direction/undefined mask, substrate, split, graph, interpolation rule, and
gauge/trivialization into one replayable object. A schema label or a transport
angle cannot supply a missing same-field payload.

Core-dependent loop placement is a frozen deterministic rule applied after
the charge-blind core seal, not a search for a large loop result. Zero, one,
many, and unresolved candidate sets remain distinct outcomes. If no core is
found, the geometry branch and predeclared no-core/off-core comparisons can
still run when their own prerequisites pass.

## 4. Independent roles and comparable coordinates

Fit, discovery, and confirmation contexts must be disjoint by document/source
and template family, including near-copy variants. Random token-level splits
do not establish independence. Group ownership is resolved before any
learned preprocessing or field estimation; all positions and tokens of one
assigned group remain within that role.

- The fit partition supplies only the permitted frame, nuisance, alignment,
  and baseline estimates. These estimates are frozen before their evaluation
  partition is read.
- Discovery evaluates the bounded, fixed panel and may propose one later
  limited checkpoint window or next-version hypothesis under a declared
  selection rule. It does not move current thresholds or erase unfavorable
  strata.
- Hidden confirmation evaluates the sealed comparison on unused groups. Its
  outcomes cannot select a layer, field, graph, core, loop, alignment,
  threshold, or checkpoint window.

All layers and graph pairings retain the same intervention-domain coordinate
definition. Later checkpoint comparisons retain the same model series,
tokenizer contract, contexts, positions, and coordinate construction. A basis
that is refit at each checkpoint needs a predeclared fit-only alignment or
gauge-invariant comparison rule; changing coordinates with the outcomes would
change the measured object. Any difference in optimizer, data mixture, or
schedule is an explicit covariate.

## 5. Rule out structure supplied by the intervention itself

A map that simply passes through two input coordinates already winds around
an input circle. Likewise, defining a response as `h(x) - h(0)` forces a zero
at the origin. Neither observation, by itself, identifies a learned core,
nonlinear model structure, or a native model manifold.

Each field estimand therefore has its own field/specification and complete
readout chain:

| Estimand | Question it can answer | Required boundary |
| --- | --- | --- |
| Full response field | What does the declared model-response construction produce? | retain any imposed origin or centering; do not call it a discovered core |
| Pass-through baseline | What pattern is already induced by the input-coordinate map and capture architecture? | same coordinate/domain contract; no learned-structure interpretation |
| Fit-only local-linear baseline | What is explained by the declared first-order response around the origin? | fit using only its assigned partition and sealed neighborhood/rank rule |
| Recomputed residual field | What remains under the explicitly defined baseline-removal operation? | reconstruct the field, amplitude, masks, cores, and loops from that residual |

The residual operation and subtraction stage must be fixed separately for
F2's vector section and F4's traceless tensor/spin-two section. A scalar
residual score is not automatically an order-parameter field. Full-field
amplitude cannot be paired with residual direction; a residual angle cannot
inherit a full-field core. Subtracting winding integers is not a measurement
of residual winding.

An identically zero residual is direction-ineligible and cannot produce a
collection of discovered cores or a valid defect boundary. Its geometry
readout may remain separately evaluable if the independent connection and
loop prerequisites permit it. Baseline accounting alone makes no semantic or
causal claim.

## 6. The output is a complete partial-pattern record

Every required checkpoint/context/layer/estimand/graph stratum retains both
F2 and F4, their same-field amplitude and eligibility, core multiplicity,
continuous geometry holonomy, and eligible sampled winding. Phase-like-regime
and transition slots remain explicit even when `not_run`. No winner between
F2 and F4 is selected, and geometry and defect failures do not erase an
otherwise evaluable independent branch.

Each slot retains its gate (`pass`, `fail`, `insufficient`, or `not_run`),
typed value or value reference, finding state, coverage and denominator,
uncertainty, stratum identities, and reason. F4 winding uses its doubled-angle
convention; continuous holonomy supplies no integer. Unrounded cycle totals,
integer residuals, and branch eligibility masks remain available for replay.

The first single-checkpoint envelope cannot evaluate a training-checkpoint
transition. A passing plumbing gate is not a scientific positive, and an
evaluable synthetic null is not a qualified model null. `fail` means a
measurement rule failed; `insufficient` and `not_run` do not mean absence.
Even after later observation, 70M remains below scientific-claim authority.

Partial or negative patterns can motivate a dated, separately versioned
exploratory hypothesis with new confirmation groups. They cannot retune the
consumed protocol, reopen its hidden partition, or choose any Pythia-160M
confirmatory input. All tested strata, not only visually compelling ones,
must remain in the record.

## 7. Later checkpoint expansion: a proposal, not a launch list

Only after the single-checkpoint envelope is operationally understood would
a separate discovery plan consider the following candidate training-step
grid:

`0, 16, 128, 512, 1000, 4000, 16000, 64000, 128000, 143000`

These are proposed coordinates, not verified available revisions, downloaded
models, frozen checkpoint hashes, or a resource commitment. The future freeze
must resolve their availability and identities before access. An unavailable
coordinate cannot be silently replaced after reading outcomes; any changed
grid requires its own documented version and rationale.

The proposed order is:

1. Use the same fixed observable panel and common coordinate contract across
   the sealed discovery checkpoint grid; retain all context and layer strata.
2. Under a bounded predeclared selection rule, seal a limited window, effect
   statistic, multiplicity treatment, uncertainty rule, and coverage rule.
3. Evaluate that unchanged window on unused confirmation groups. Sparse
   checkpoint spacing limits temporal localization; it does not identify an
   unobserved sharp transition.
4. Only under a further authorization, assess the same comparison on a
   separately identified training seed, with architecture/data/tokenizer
   comparability declared and no outcome-driven window movement.

Smooth drift, one spike, sampling/coverage loss, an instrument detection
threshold, or a change visible only after selecting a field/layer/graph is
not a transition. A candidate-level transition test would additionally need
the M9 sensitivity and independent field/core plus geometry/defect conditions
specified by the measurement-chain design. Exercising that test on 70M is
still plumbing; it cannot confer SCI-S1/S2 or scientific authority.

## 8. Resources and stopping rules remain unresolved

No context counts, number of probes, repetitions, domain resolution, density
range, amplitude/noise grid, dipole-separation grid, wall-time budget, memory
limit, disk allowance, accelerator choice, or retry allowance is frozen here.
The graph cross, both sections, all layer strata, baseline estimands, controls,
and uncertainty repetitions must be included in a future cost estimate.

Furnace is a possible later execution resource only. Its availability does
not authorize data movement, private context use, model access, or remote
execution, and no capacity or performance claim is made without a separate
measurement. A later local/remote choice must bind the exact host/runtime,
approved data scope, destination, resource ceilings, and stop policy.

The future protocol must stop within those ceilings, preserve failed attempts,
and distinguish infrastructure failure, an adverse evaluable gate (`fail`),
and missing evaluability (`insufficient`). It must not widen a threshold,
shrink the required panel, select another checkpoint, or extend the resource
budget after seeing an unfavorable result under the same frozen identity.

## 9. Required next decision and unchanged gates

The next review should inspect the synthetic prototype's actual outputs and
remaining gaps, then decide whether to prepare a separately versioned bounded
70M plumbing protocol. That later preparation must resolve every item marked
unresolved above, separate source/input freeze from launch authorization, and
declare exact-one lifecycle and durable replay artifacts before access.

This plan does not freeze or execute P4 v0.3, repair or rerun D7, advance D8,
qualify M9/SCI-S1, unblock SCI-S2, or relax the Pythia-160M gate. Pythia-160M
contexts, split membership, thresholds, exclusions, and learned preprocessing
must be frozen independently through their own future process; 70M outcomes
cannot select them. No model-derived order parameter, verified core, model
topology, thermodynamic phase, semantic state, causal effect, scientific
result, publication claim, milestone, or release is established by this
document.
